# 扩充层编写通用指南（所有扩充批次代理必读）

你的任务：把既有学科指定章节的每一节正文，从当前约 700–1600 字的概览式，**深度扩写为 2600–3600 字的教材级小节**。这是「超集式扩写」：原正文的所有知识点、数值、术语、结论必须全部保留（可以重新组织语言），在其之上补充深度。

## 工作流程
1. 读 /home/z/my-project/worklog.md 最后 60 行了解背景。
2. 用 Read 工具按批次简报给出的**行号区间**读原学科文件中你负责的章节（每次读一章的区间，逐节细读）。
3. 读测验题文件中你负责章节的题目（用 `rg -n "chapterId: '{subjectId}-ch{N}'" src/data/quiz/{subjectId}.ts` 定位），**测验题考查的每一个数值/结论在扩写后正文中必须仍然成立**（题目与选项本身不改）。
4. 为每一节撰写完整替换正文，写入批次输出文件（简报指定路径与导出名）。

## 输出文件格式（严格遵守）
```ts
// {subjectId} 第 {a}–{b} 章正文深度扩充（超集式：保留原有全部知识点并扩写）
export const {exportName}: Record<string, string> = {
  '{subjectId}-ch{n}-s{m}': `## 第一个 H2 标题

正文……（2600–3600 字符）……`,
  // ……本批次所有小节，一个不落
}
```
**不要**在输出文件里放 keyPoints/terms/章标题——只放正文字符串。主控会把你的文件接入合并层，keyPoints/terms/测验题全部原样保留。

## 内容硬性要求
1. 每节正文 **2600–3600 字符**（低于 2400 会被校验拦截）；每节 **至少 4 个 `## ` H2 标题**（原有的 H2 主题必须保留，可改写措辞，并新增 2–3 个深化小节）。
2. 配图在渲染时自动插入到 H2 边界之间——H2 数量充足且分布均匀能让插图排版更好；**不得删除与既有插图 caption 呼应的 H2 主题**（例如原来有「α 螺旋」「β 折叠」小节，扩写后这些主题仍需存在）。
3. 扩充方向（按需选择 2–4 种）：①机理细节分步骤展开；②定量数据（数值、速率、能量、尺寸、浓度）；③经典实验与证据链（人物、年代、结论）；④生理/病理/工业应用联系；⑤易混淆概念对比（用 Markdown 表格）；⑥历史沿革与前沿衔接。
4. 每章至少保证 1–2 张 Markdown 表格（`| A | B |` 形式，表头分隔行用 `|---|---|`）。
5. 中文学术语气；术语首次出现标注英文；重点术语 **加粗**；无 emoji、无代码块、无 HTML、无图片链接。
6. **正文是模板字符串**：内容中严禁出现反引号 ` 与 ${ 序列；引用用「」；不用嵌套三级以上标题（只用 ##）。
7. 数值必须可靠（教材口径），不确定的用区间表述，不得编造。
8. 原创撰写；保持与原小节一致的知识边界，不引入与本节无关的姊妹章节详细内容（点到为止用「参见」句式）。

## 校验（必须通过）

```
cd /home/z/my-project && bun run scripts/validate-expansion.ts <输出文件路径> <subjectId> <章号...>
```

- 完成后用 bash `cat >> /home/z/my-project/worklog.md << 'EOF' …EOF` 追加工作记录（含 Task ID / Agent / Task / Work Log / Stage Summary），不得覆盖他人记录。
